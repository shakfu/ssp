# scsy changes for sapf-sc

[sapf-sc](https://github.com/shakfu/sapf-sc) compiles sapf programs to SynthDefs. Two of its features could not run on the SSP: polyphony (`ola`, one synth per sound) and buffers (sample playback with `sf>` and `playbuf`, and wave tables for `osc`). A SynthDef can neither start synths nor load buffers, so scsy gained two features: it plays scores, and its sidecar names buffers. User docs: [README](../../plugins/scsynth/README.md#scores); changelog: Unreleased.

## Scores

A score is an NRT command file, as sapf-sc's `>nrt` writes: the main def, every voice def, timed `/s_new`s, and buffer commands for wave tables. Two alternatives were weighed: unrolling a fixed number of voice slots into one def, which repeats each slot's random choices every cycle, or playing the score. The score keeps sapf's per-voice randomness for its whole length; it was chosen.

| File | Change |
|-|-|
| `ScsyDef.h/.cpp` | `readScore`: parses the file into the main def, the voice defs, buffer commands and timed events. `resolveBufferPath`: a relative `/b_allocRead` path becomes relative to the score's folder. |
| `ScWorld.h/.cpp` | `loadScore`: runs the buffer commands and receives the voice defs, under names of its own, then loads the main def with `loadDef`. A feeder thread sends each voice as a bundle timed 0.5 s ahead of the World's clock, and loops at the score's end. `stopScore` ends it on the next load or close. `load(path)` accepts scores. |
| `ScsynthEngine.h/.cpp` | `compile` recognizes a score; its main def takes the controls and sidecar as a `.scsyndef` would. |

- **Clock:** the driver already runs scsynth's scheduler per block, on OSC time that advances with the samples (`mOSCbuftime`). The feeder reads it through `oscNow_`, which `process` writes after each callback. A stalled host therefore stalls the score.
- **Voice order:** voices go into group 901, placed before the main synth, so the main synth can read the buses they write.

## Bug: replies dropped during loads

`ScWorld` keeps scsynth's replies in a ring of 16 slots and drops a reply its slot cannot hold. A score with 30 wave-table buffers sends more than 30 commands that each answer `/done`. The burst filled the ring, so the `/synced` that ended the load was dropped, and the load reported "scsynth did not answer".

`sendInBatches` now sends 8 commands at a time, each batch closed by `/sync`. The score fixture has 20 extra buffers for this. Without batching, its test fails.

## Buffers

`// @buf N path` and `// @buf N alloc SECONDS [CHANNELS]` in the sidecar, as [scsy-buffer.md](scsy-buffer.md) proposed. That doc's status line now says it is implemented.

| File | Change |
|-|-|
| `ScsynthEngine.h/.cpp` | `bufferSpecs`: parses the lines, resolves relative paths from the def's folder, opens each file with libsndfile for its size and modification time, and enforces the 256 MB cap before anything is sent. `compile` calls `loadBuffers` before every load. |
| `ScWorld.h/.cpp` | `loadBuffers`: sends `/b_allocRead` or `/b_alloc` only for lines the World does not already hold unchanged, so a recording in an `alloc` buffer survives a reload. A successful load frees the numbers it no longer names. |
| `CMakeLists.txt` | `ScsynthEngine.cpp` gets the deps include folder, for `sndfile.h`. Not yet built for the SSP. |

## Tests

| File | Change |
|-|-|
| `tests/scsynth_test.cpp` | `score()`: voices start at their times, block-aligned, and loop; a later def stops them. |
| `tests/scsy_test.cpp` | A score through the engine with its sidecar. `@buf`: a file plays exactly; a missing file fails and the running def goes on; a recording survives an unchanged line and not a changed one; the memory cap; unnamed buffers are freed. |
| `tests/defs/score.py`, `score.osc` | The score fixture, written with nanosynth. |
| `tests/defs/buffers.py`, `buf*.scsyndef`, `click.wav` | Buffer test defs and a 64-frame WAV. `defs.py` is untouched, so the committed defs are not regenerated by another nanosynth version. |

These tests were run on macOS against libscsynth built by hand, since `scripts/build_deps.sh host` is Linux only; `make test` on Linux has not run them yet.
